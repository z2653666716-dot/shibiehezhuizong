# 交付与人工验收指南

## 当前软件范围

当前收尾基线为`baseline/tested-v0.3.6`，运行版本`0.3.6-distance-reentry`；固定标签`v0.3.6-tested-baseline`保留本轮整合快照。原8446基线、各功能分支及main均保留，后续收尾从新基线开展。

浏览器/IP两路检测、长按锁定、身份保持、照片注册、PWA资源、可选录制、基准和源码打包已经实现。新基线通过`run_identity.ps1`启用BoT-SORT、OSNet和人脸辅助，普通启动仍保持原ByteTrack/appearance模式。软件自动检查91项通过，距离重入已有本轮用户正面复测反馈；自动验证及有限现场反馈不能代替完整准确率验收。

当前禁止保存和外传实拍媒体。现场测试需要事先说明用途、时长、传输范围并重新取得同意；不因用户说“继续”而打开设备。需要演示视频时必须另行明确允许保存，否则不要录制。

## 课堂一键启动

1. 电脑开启移动热点，手机连接；当前热点地址为192.168.137.1。
2. 编辑器打开项目根目录`run.py`，点击右上角运行三角按钮。自动使用项目环境，无需输入PowerShell或激活Conda。
3. 等待`Application startup complete`，手机浏览器打开`https://192.168.137.1:8450`，确认版本0.3.6-distance-reentry，再手动开始检测。浏览器模式的实时画面在手机上，电脑投影同屏仍需另行准备投屏。
4. 结束先点手机“停止检测”，确认摄像头提示结束，再在运行终端按Ctrl+C。不要重复点击运行开启多份服务；端口占用时入口会拒绝，不会结束已有程序。

`run.py`只启动服务、不打开设备；参数与原run_identity.ps1一致。已准备的热点证书和模型仍从项目目录读取，移动或重新安装项目时不能只复制这个文件。

## 回来后按顺序检查

1. 手机与电脑同一Wi-Fi，打开服务终端给出的HTTPS页面，先不启动摄像头，确认页面和安全环境可用。
2. 在本次明确同意使用摄像头后，由用户开始和停止。短按人物框变黄；长按0.6秒后应变绿；取消手势不能锁定。锁第二个人应解除第一个，再次长按绿框应取消且不自动恢复；照片登记也替换旧目标。
3. 让同一人离开画面10秒再返回。记录实际是否恢复同一ID、耗时多少；失败如实记失败，不通过调低门槛制造通过。
4. 第二个人进入或从前方经过。检查第二个人不被误绑；相似穿着属于已知困难场景。
5. 用户手动选一张已允许使用的清晰单人照，查看实时画面上方常驻的登记成功/失败、ID及缩略图，再检查是否自动匹配；hybrid模式支持清晰人脸特写，appearance模式仍以人物外观为依据。多人、无人或质量不足时按实际提示记录。当前照片仅内存处理。
6. 删除身份后应该回白框，停止检测后预览消失、浏览器摄像头使用提示结束。IP模式还要在手机停止App。
7. Android浏览器添加到主屏幕后打开，检查是否没有地址栏；离线只能打开界面，不能检测。

用户已完成的有限现场反馈见branch_testing.md；未测项目不勾选通过。此前各次摄像头授权随测试结束，不自动覆盖后续复测。

## 正式标定与论文数据

默认相似度门槛还没有用真实、跨帧人物配对标定。公开bus单图的亮度增强不是重入测试，只有16组增强同人对和6组异人对，不能写成正式识别准确率。

如有明确授权的既有数据，按README配对格式为每类准备至少15对，再运行 `scripts/calibrate_reid.py --pairs ...`。应包含不同姿态、光照、遮挡以及同色穿着的不同人。没有授权时不要为补数据擅自采集或保存实拍。

可引用的实际软件数值报告：

- `outputs/acceptance/full_stream_60s.json`：公开样例完整链路的60秒检查和内存采样。
- `outputs/bench/detection_benchmark.json`、同名CSV：12组本地检测器基准。
- `outputs/reid/public_diagnostic.json`、`color_diagnostic.json`：外观融合与纯颜色的公开增强诊断。
- pytest控制台与 `PROGRESS.md`：算法边界、接口、浏览器、隐私限制和清理检查。

检测器FPS不等于网络端到端FPS；服务端处理耗时不包含采集、传输、浏览器等待。报告中必须保持这些区别。

## 源码包与课程最终包

既有`outputs/delivery/vitrack_complete_features.zip`仍对应0.3.5；新基线0.3.6修复尚未重新打包。后续收尾应先同步打包工具的hybrid模型清单，再对新包独立解压验证，不把旧包当作新基线交付。

`scripts/package_source.py` 生成源码包，包含入口、网页、脚本、测试、必要模型、公开样例及来源；排除环境、证书、私有.env、临时目录、输出和实拍媒体。清单带每个文件SHA256，压缩和解压体积均检查不超过200MiB。

没有学号姓名时输出中性文件名，不假造个人信息。可在最终资料准备好后执行：

```powershell
.\envs\vitrack\python.exe -X utf8 scripts/package_source.py --student-id 实际学号 --student-name 实际姓名
```

注意该命令仍只是源码包命名，不能把它当成已经包含全部课程材料。

课程最终提交仍需以下内容。论文/报告正文与最终实拍视频按原方案由本人完成，未知个人信息和未完成的实验不作编造：

- ≥3000字学术论文正文，包含真实引用、方法、真实实验与局限。
- 课堂实验报告的实际模板与正文，确认是否与本项目同题。
- 5分钟课程汇报PPT应根据实际现场验收结果整理，不放入未进行的效果截图或实验数据。
- 3～5分钟成果演示视频及是否另需课堂实践视频，录制前须另行允许保存。
- 学号、姓名、具体截止日期、课堂报告要求及教师确认项。

原始实施方案保持不改，相关要求与演示时间安排仍以其第11/14/15节为准。

## 干净目录复核

源码解压到独立目录后，用该目录为工作目录运行编译/测试及本机服务。必要模型均从包内读取；不复制原电脑证书和私有配置，也不把原环境塞进包。

现有环境可以临时用于检查源码可导入和运行；这不等于在另一台全新电脑重新安装了全部依赖。首次安装仍按README三步启动，GPU不可用时显式改DET_DEVICE=cpu。
