# 身份跟踪策略

## 三类依据

轨迹关联、人脸匹配、身体匹配分别回答不同问题：BoT-SORT判断前后帧的框是否连续，SFace比较可用人脸，OSNet比较身体外观。它们的结果由`HybridSession.evidence()`组合，不能把轨迹编号相同直接当作身份确认。

可靠人脸可以确认身份；明显矛盾的清晰人脸会否定当前绑定。已有目标在人脸暂不可用时，可以凭身体和运动连续性保持跟踪。身体也不足、轨迹中断或多人归属不清时，重新进入确认流程。

## 人脸质量与归属

`FaceEncoder.read()`先检测人脸，再检查尺寸、清晰度和关键点的粗略姿态。过小、模糊、极端角度表示缺少可靠观测，不直接当作另一个人。

`FaceEncoder.associate()`根据人脸位置建立可能的身体归属，在相互关联的框组内做一对一匹配。只有所有可行匹配中都成立的归属才采用。没有轨迹号的新白框也参与约束，避免将未稳定出现的旁人忽略。

## 候选确认

`process()`先核验已有绑定，再比较未绑定轨迹对同一身份的分数。候选之间必须有领先差距，不能按检测数组顺序抢占身份。

`progress_candidate()`默认需要6份实际通过的观测。确认窗口默认12个已处理帧，可容忍最多连续2帧的中性缺失；缺失帧不增加成功次数，距离最近成功观测还受时间限制。明确异人脸、竞争或过长缺失会清空进度。

`update()`仅在同一轨迹短时漏检、返回位置连贯、时间未超限时恢复原进度。新轨迹不继承旧候选。画面分辨率变化可能重建轨迹，身份模板仍留在当前会话内。

## 连续保持

人脸归属暂不清晰，但原轨迹连贯、身体可靠且明显领先旁人时，允许有期限的连续保持。这个等待不会刷新最近可靠确认时间，不能靠同一份弱证据无限延长。

当前只有头部时，不要求不存在的全身特征；明确的人脸位置和运动观测可以支持连续跟踪，但轨迹中断后仍需重新匹配。

前端将`verification=continuity`显示为“跟踪中”，`candidate`显示为绿色虚线“识别中”。二者分别对应保持已有目标和确认候选。

## 距离变化与模板更新

远处手动锁定时，脸可能太小，只能登记身体。如果始终只保存远景模板，走近后的身体差异又可能阻止第一份人脸登记。

`remember_body_transition()`因此允许原手动轨迹有限记住过渡距离的身体外观：当前强匹配至少0.85，身体分数明显领先旁人，运动连续，且与最初模板仍达到原维持门槛。未比较的新人物、突然变化、失锁或失去连续性的轨迹不具备学习条件；新入镜轨迹没有原来的学习许可。

`remember_confirmed()`随后累计6份彼此一致的清晰正脸，才补入第一份人脸模板。已有绑定时每3帧提取一次人脸特征，主动跳过的帧既不计成功，也不抹掉之前的可靠采样。

最初模板始终保留，模板总数有限。已有可靠人脸确认后可以补充身体姿态；临时脸样本与学习许可在取消、删除、停止时清除。

## 重入与边界

已经有人脸模板的目标离开后，新轨迹需要重新取得人脸匹配证据，不只凭相似衣服恢复身份。尚未取得清晰人脸、身体变化过大时，重入仍可能失败；单次连续绿框不代表已完成跨距离身份登记。

目前没有正式跨人物评测集，默认门槛属于实现参数。`tests/test_distance_reentry.py`等用已知向量验证规则，不能据此报告实拍识别准确率。
